# 輕量任務治理

## 定位

這是整個工作流程的治理層，不是只檢查某個 Skill 的清單。

一個任務可能同時使用：

- Skill
- Prompt 或 SOP
- 子 Agent
- 外部工具
- 檔案操作
- 人工決策

治理機制要看整條工作鏈是否達成目的，不把責任切碎到只檢查其中一個工具。

## 核心原則

1. **結果優先**：檢查是否完成使用者真正要的事，不為了流程而流程。
2. **比例原則**：任務越簡單，治理越輕；不要用大型審計處理小問題。
3. **證據優先**：沒有觀察到的錯誤，不當成錯誤；沒有證據的風險，不升級成警告。
4. **避免無病呻吟**：不因個人偏好、假想邊界情境、重複檢查或純粹想得更完美而打斷流程。
5. **不把未知冒充失敗**：未驗證就寫「未驗證」；只有實際不符合標準才寫「失敗」。
6. **可改進才記錄**：紀錄要能幫助下次更快、更準或更安全；不能帶來改進的細節不必保存。
7. **記憶要節制**：一次性執行紀錄不自動升格為永久規則；穩定規則要經過重複證據或使用者確認。
8. **保持可逆**：涉及檔案與設定時，先說明影響範圍，避免未確認的不可逆修改。
9. **Source of Truth 分離**：程式碼、測試、研究證據與任務紀錄各自負責，不用任務紀錄取代真正的產出。

## 什麼情況才值得提出問題

### 應該提出

- 實際執行失敗或輸出明顯不完整。
- 不符合使用者已說明的成功條件。
- 可能造成資料遺失、隱私洩漏或不可逆修改。
- 已知的既有功能被這次修改破壞。
- 缺少會直接影響結果的關鍵輸入。
- 使用者必須在兩個不同結果之間做選擇。

### 不要主動提出

- 沒有證據的假想風險。
- 只是風格或個人偏好不同。
- 已經有其他檢查涵蓋的重複提醒。
- 不影響交付結果的小瑕疵。
- 為了讓報告看起來完整而列出的泛泛警告。
- 完成後才臨時創造的新標準。

## 任務分級

### L0：簡單對話或讀取

適用：回答問題、閱讀單一檔案、簡單說明。

- 不建立任務記錄。
- 不做形式化驗證。
- 正常回答或回報讀取結果即可。

### L1：單一步驟或單一檔案操作

適用：改一個檔名、讀取後做一個小修改、建立一份簡短文件。

- 確認結果是否真的產生。
- 回報檔名與位置。
- 不建立完整 Trace，不做假想風險分析。

### L2：多步驟工作或多個執行單位

適用：同時使用多個 Skill、Prompt、子 Agent 或工具，或修改多個相關檔案。

- 先列出簡短目標與 1～3 個成功條件。
- 只記錄有意義的步驟與產出。
- 完成後做與目標直接相關的驗證。
- 必要時建立簡短的 `task-runs/` 紀錄。

### L3：系統級或高影響修改

適用：修改 `AGENTS.md`、Skill、Prompt、設定、依賴關係、公開內容，或執行不可逆／高風險操作。

- 執行前說明影響範圍。
- 使用驗證清單與實際證據。
- 檢查已知的下游影響。
- 留下交接資訊。
- 只有在真正需要使用者決策時才停下來詢問。

## 任務生命週期

### 1. 執行前

只做必要的規劃：

- 用一句話定義目標。
- 判斷 L0～L3。
- 列出最多 1～3 個成功條件。
- 確認是否需要 Skill、Prompt、子 Agent 或工具。

簡單任務不要硬套完整格式。

### 2. 執行中

- 只記錄有意義的事件，不記錄每個想法或每次讀檔。
- 子 Agent 必須回傳：完成內容、產出位置、證據、仍不確定的地方。
- 失敗時記錄實際錯誤與已嘗試的方法，不推測不存在的原因。

### 3. 執行後

依序確認：

1. 產出是否存在。
2. 產出是否符合使用者要求。
3. 是否有實際錯誤或遺漏。
4. 是否需要交接或保存可重用經驗。

回報時使用以下結果之一：

- **完成**
- **完成，附一項注意事項**
- **需要使用者確認**
- **未完成，說明實際原因**

不要為了湊格式硬加「風險」或「改善建議」。

## 追蹤與記憶的分層

- **執行紀錄（Trace）**：這次任務發生了什麼，短期、可追溯。
- **工作日誌**：重要操作的可讀摘要，供使用者回顧。
- **交接紀錄（Handoff）**：下一次對話要從哪裡接手。
- **流程記憶（SOP／Skill）**：重複出現、已驗證、值得重用的方法。
- **系統規則**：穩定且影響範圍大的規則，需使用者確認或充分證據。

預設只留下必要的 Trace 與工作摘要；只有以下情況才提出是否升級成 Skill／SOP：

- 流程重複出現。
- 使用者明確要求。
- 這次修正確實解決了可重現的問題。
- 保存後能明確減少未來成本或錯誤。

## 實作入口

需要完整追蹤時，使用：

- `references/task-run-template.md`
- `references/handoff-template.md`
- `references/verification-checklist.md`

`task-runs/` 紀錄只在 L2～L3 或使用者要求時建立；L0～L1 不必建立檔案。
