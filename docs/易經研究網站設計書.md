# 易經研究網站設計書（草案）

- **版本**：v0.1
- **日期**：2026-09-01
- **狀態**：草案；起卦方式已確認，知識來源待連線
- **暫定定位**：以卜卦結果為入口，協助使用者先看懂卦象結構，再閱讀《周易》卦辭、爻辭與相關研究資料。
- **第二版補充**：`docs/易理研究室第二版規格、需求與開發計畫.md`

## 1. 問題重述

建立一個易經研究網站。使用者完成起卦、取得六爻後，網站先清楚指出本卦、變爻與之卦，並依可說明的卦象規則提供初步結構分析，例如變爻位置、承／乘、得位／失位等；接著列出所有變爻的爻辭。當變爻數量達三爻以上時，另外顯示之卦的卦辭。易經知識內容以使用者 NotebookLM 的「易經經典」筆記本為主要參考來源。

## 2. 設計目標

1. **先看懂卦象，再閱讀經文**：結果頁的第一屏先呈現結構摘要，不直接把使用者丟進長篇古文。
2. **所有判斷可追溯**：每個「得位」「乘」「承」等標籤，都能查看它依據的規則。
3. **變爻不遺漏**：無論有 1、2 或 6 個變爻，都逐一列出；0 個變爻則明確顯示「無變爻」。
4. **內容與演算分離**：卦象計算由程式規則處理，經文與解說由可校訂的資料內容提供。
5. **以研究輔助為定位**：初步分析是閱讀提示，不宣稱取代完整解卦或個人判斷。

## 3. 參考網站整理

參考：<https://iching.ileatw.com/>

可借鏡的部分：

- 主要入口分成「易經卜卦」「周易六十四卦」「案例分享」。
- 卜卦結果同時呈現本卦、變卦、六爻數字與變爻位置。
- 以顏色標示變爻，並說明六、七、八、九及 0～6 個變爻的基本處理方式。
- 六十四卦頁面包含卦名、上下卦、卦辭、彖／象、注釋、白話釋義與逐爻內容。
- 參考網站的結果頁偏向「提供卦象與查閱入口」；本網站將再增加「結構分析卡」與「所有變爻集中閱讀」功能。

> 參考網站只作為功能與資訊架構參考，不直接複製其程式碼或未經確認的內容。

## 4. 使用者流程

### 4.1 起卦前

1. 進入「開始卜卦」。
2. 輸入問題（可選，但建議輸入）。
3. 選擇「揲蓍法」起卦。
4. 顯示起卦說明：由初爻開始，依序取得初爻、九二／六二……上爻。

### 4.2 起卦中：逐步互動揲蓍法模擬

1. 顯示目前進度：第幾爻、該爻的第幾變；完整一卦共 6 爻、18 變。
2. 每一變依序呈現「分二 → 掛一 → 揲四 → 歸奇」四個步驟。
3. 使用者按下「進行下一步」後，畫面顯示本次操作的蓍草數、過揲之數與剩餘本數。
4. 同一爻完成三變後，系統計算並顯示 6、7、8 或 9，以及老陰／少陰／少陽／老陽與是否為變爻。
5. 顯示剛完成的爻，再由初爻向上進行下一爻。
6. 完成六爻後，顯示完整卦象；使用者確認後進入結果頁。
7. 起卦過程可返回上一個步驟或重新開始，但必須明確提示重新開始會捨棄目前模擬結果。

### 4.3 結果頁呈現順序

#### A. 卦象總覽

- 問題、起卦時間、起卦方式。
- 本卦名稱、卦序、上下卦與卦象圖。
- 之卦名稱、卦序、上下卦與卦象圖。
- 變爻數量與位置，例如「2 個變爻：九二、六五」。
- 以顏色、圖示及文字三種方式標示變爻，不只依賴顏色。

#### B. 初步結構分析

先顯示簡短摘要，再提供逐爻詳情：

- 本卦／之卦的變化摘要。
- 變爻集中在哪些爻位。
- 各爻的陰陽狀態與爻值：6、7、8、9。
- 得位／失位（位正／位不正）。
- 得中／不中：二爻、五爻為中位。
- 正應／無應或相關應爻關係。
- 適用時顯示承／乘及相鄰爻的關係。
- 每一個標籤都提供「這個詞代表什麼」的說明入口。

初步分析文字採取「結構描述」為主，例如：

> 六三為陰爻，處於陽位，屬失位；與下方陽爻形成乘的關係。此為卦象結構提示，尚未包含針對個人問題的完整判斷。

#### C. 變爻爻辭

集中列出所有變爻，每一爻一張卡片：

- 爻位：初爻、二爻、三爻、四爻、五爻、上爻。
- 爻名：初九／初六、九二／六二等。
- 原始爻值：6 或 9 表示變爻。
- 爻辭原文。
- 可選的象傳、注、白話解釋與資料來源。
- 該爻的結構標籤：得位／失位、得中／不中、承／乘、應等。

若沒有變爻，顯示「本卦無變爻，以下以本卦卦義作為閱讀入口」，不顯示空白區塊。

#### D. 之卦卦辭

- 永遠可以顯示之卦名稱，方便理解卦象轉變。
- **變爻數量達 3 個以上時**，在結果頁主動顯示之卦卦辭。
- 之卦卦辭與本卦卦辭分開標示，避免使用者誤以為兩者是同一段經文。
- 可連往完整的之卦資料頁。

#### E. 延伸閱讀

- 本卦完整資料。
- 之卦完整資料。
- 易經術語說明：本卦、之卦、變爻、得位、得中、承、乘、應等。
- 使用的內容版本與來源。

## 6. 卜卦與分析規則草案

以下是程式實作前需要由 NotebookLM 內容與使用者確認的規則規格；目前先作為設計介面，不視為已完成的經學定稿。

### 6.1 爻值與陰陽

建議以六爻陣列由下往上儲存：

```text
position 1 → 初爻
position 2 → 二爻
position 3 → 三爻
position 4 → 四爻
position 5 → 五爻
position 6 → 上爻
```

| 爻值 | 狀態 | 本卦陰陽 | 是否變爻 | 變後陰陽 |
|---|---|---|---|---|
| 6 | 老陰 | 陰 | 是 | 陽 |
| 7 | 少陽 | 陽 | 否 | 陽 |
| 8 | 少陰 | 陰 | 否 | 陰 |
| 9 | 老陽 | 陽 | 是 | 陰 |

### 6.2 本卦與之卦

1. 6、8 視為陰爻；7、9 視為陽爻，組成本卦。
2. 只有 6、9 是變爻。
3. 將 6、9 的陰陽翻轉，得到之卦。
4. 變爻位置必須以 1～6 明確列出。

### 6.3 位正不正

初步採常見位置判斷：

- 一、三、五為陽位。
- 二、四、上為陰位。
- 陽爻處陽位、陰爻處陰位，標示「得位／位正」；反之標示「失位／位不正」。

此規則必須以「易經經典」筆記本採用的解釋版本做最後確認，並在網站中標示規則來源。

### 6.4 得中

- 二爻、五爻為中位。
- 顯示「得中／不中」時，需和「得位／失位」分開，不能混成同一個標籤。

### 6.5 承、乘與其他關係

結果頁應以相鄰爻為單位顯示關係，而不是把「承」或「乘」當作每一爻固定不變的屬性。規則引擎需保存：

- 關係涉及的兩個爻位。
- 下爻與上爻的陰陽。
- 關係名稱：承、乘或無特定關係。
- 使用的規則版本與說明。

「比」「應」等其他關係先保留資料模型與 UI 擴充位置，待 NotebookLM 內容確認後再決定是否納入 MVP。

## 7. 內容設計

### 7.1 每一卦的內容欄位

- 唯一 ID、卦序、卦名、別名。
- 上卦、下卦、上下卦的二進位／陰陽表示。
- 卦象圖（由程式產生 SVG，不直接依賴外部圖片）。
- 卦辭原文。
- 彖傳、象傳；文言等僅在來源確實提供時列為可選欄位。
- 注、白話解釋或研究筆記，並保留內容類型標籤。
- 六爻資料。
- 可選的應用解說，例如時運、財運、婚嫁／婚姻、疾病；原始分類名稱另行保存。
- 相關術語與本卦／之卦交叉連結。
- 錯卦、綜卦、互卦等相關卦連結（列為衍生／進階欄位，不在第一版自動解讀）。
- 來源、版本、引用位置、校訂日期與校訂狀態。

### 7.2 每一爻的內容欄位

- 所屬卦 ID。
- 爻位數字（1～6）、顯示位置（初、二、三、四、五、上）。
- 爻名：初九／初六、九二／六二等。
- 爻辭原文。
- 象傳。
- 注、白話釋義或研究筆記，並保留內容類型標籤。
- 可選的應用解說，例如時運、財運、婚嫁／婚姻、疾病。
- 可引用的來源段落、來源版本與內容編輯備註。

### 7.3 參考網站與參考資料夾的欄位對照

「周易六十四卦」索引頁本身是以**上卦 × 下卦的 8×8 矩陣**呈現六十四卦，適合轉成網站的索引資料與卦象查找鍵。每個矩陣格至少對應：上卦、下卦、卦名、卦序與詳細頁連結。

參考網站的單一卦頁則可作為內容層級參考，觀察到的欄位包括：

- 卦序、卦名、上下卦。
- 卦象圖。
- 卦辭、彖、注、釋。
- 象、釋。
- 六個爻位，各自包含爻辭、象、注、釋。
- 卦與爻的應用分類解說：時運、財運、婚嫁／婚姻、疾病。
- 發佈日期、作者、分類、標籤等 CMS metadata。

其中 CMS metadata 與易經內容欄位分開保存，不讓作者、發佈日期等網站管理欄位混入卦象規則。參考網站的實際內容仍須由 NotebookLM 來源與人工校訂決定是否採用。

`參考資料/iching_website_design_spec.md` 進一步提醒：朱子／傳統辭象占、高島易斷、察象占、納甲法與一卦六伏法必須分開，不能把流派專屬欄位直接混入共同 Hexagram schema。因此第一版只建立「揲蓍法起卦 + 卦象結構標籤 + 經文閱讀」核心；`na_jia`、`shi_yao`、`cc_six_latents`、五行六親、伏卦等列為日後獨立的 rule profile，不放進第一版預設結果。

`參考資料/易經六十四卦_白話 Final_Mike.docx` 與 `.pdf` 的目錄均列出卦一至卦六十四；抽取文字檢查各找到 384 筆爻位標題。兩者可作內容校訂對照，但不取代 NotebookLM 的來源引用。

### 7.4 NotebookLM 內容匯入原則

目前已確認 NotebookLM「易經經典: Guides to the Zhouyi」可存取，內含 8 個已完成索引的 PDF 來源；其中 `易經六十四卦_白話 Final_Mike.pdf` 可作為六十四卦與 384 爻的主要欄位參考，`2.起卦法與判定.pdf` 可作為揲蓍法與變爻規則參考。

1. 以 NotebookLM 摘要與引用作為研究輸入，不把摘要直接視為已校訂網站內容。
2. 將原文、解釋、規則與編輯者備註分開保存。
3. 每筆資料附上來源名稱、版本或段落位置，避免日後無法追溯。
4. 先人工校訂內容，再放入網站資料檔；不讓網站在執行時依賴 NotebookLM 才能顯示基本結果。
5. 若不同資料對同一概念有不同說法，網站先標示「版本差異」，不自行合併成唯一答案。

### 7.5 目前研究結論與限制

- 揲蓍法可支援 50 根置一不用、49 根演算、三變成一爻、十八變成一卦的流程。
- `易經六十四卦_白話 Final_Mike.pdf` 可支援六十四卦與 384 爻的初步資料建模，乾卦另有用九、坤卦另有用六；直接檢查來源全文也找到 384 筆爻位標題。
- 來源卦序標題有排版／OCR 變形，不能只靠文字正規表示判斷章節完整；正式匯入仍需人工校訂。
- 應用分類如時運、財運、婚嫁／婚姻、疾病散見於文字，不視為已完成的標準化欄位。
- 來源有錯字、異體字、斷句、排版與亂碼問題；正式匯入前必須逐筆人工校訂。
- `參考資料/iching_website_design_spec.md` 含有較進階的流派與占斷建議；第一版僅吸收其「資料分層、規則隔離、證據分層」原則，不直接啟用其個別占斷結論。
- NotebookLM 的回答曾出現錯誤爻位索引，因此所有規則仍需以來源原文與人工案例測試為準。

研究證據保存於 `research/易經網站/`。

## 8. 技術方向（待確認）

由於目前專案尚無網站程式，MVP 建議採：

- `React + TypeScript + Vite`。
- 靜態前端，不先建立帳號、後端或資料庫。
- 易經資料以 JSON 或 TypeScript data module 保存。
- 卦象計算與關係判斷寫成沒有畫面的純函式，方便單元測試。
- UI、內容資料、規則引擎分離。
- 手機優先、繁體中文、鍵盤可操作、變爻不可只靠顏色辨識。

建議的模組方向：

```text
src/
├── domain/iching/
│   ├── cast.ts              # 爻值與卦象計算
│   ├── hexagram.ts          # 本卦／之卦辨識
│   ├── relationships.ts     # 得位、得中、承、乘、應等
│   └── types.ts
├── data/
│   ├── hexagrams.json
│   ├── lines.json
│   └── glossary.json
├── features/divination/
├── features/hexagrams/
└── components/
```

## 9. 分階段開發

### Phase 0：規則與來源確認

- 起卦方法已確認為揲蓍法。
- NotebookLM 目標筆記本與 8 個已索引來源已確認。
- 依來源原文核對「承／乘」「位正不正」「應」的採用規則。
- 決定內容是否包含彖、象、注、白話釋義。

### Phase 1：最小可行版本

- 以逐步互動的揲蓍法模擬取得六爻。
- 顯示六爻十八變的進度與每變結果。
- 計算本卦、變爻、之卦。
- 顯示完整卦象與所有變爻。
- 顯示得位／失位、得中／不中及經人工核對後的承／乘規則；核對前只顯示相鄰關係資訊。
- 變爻達三爻以上時顯示之卦卦辭。
- 以少量已校訂資料驗證結果流程。

### Phase 2：完整內容閱讀

- 建立六十四卦索引與詳細頁。
- 匯入完整卦辭、爻辭與研究資料。
- 加入術語字典、來源引用與版本標示。
- 增加搜尋與本卦／之卦交叉閱讀。

### Phase 3：使用體驗改善

- 真實擲錢或其他起卦動畫。
- 卜卦紀錄、書籤與分享。
- 案例研究與使用者筆記。
- 視需要評估 AI 輔助摘要；不得取代規則引擎或未經來源支持的經文解釋。

## 10. 驗收條件

### 功能驗收

- 六爻完成後，能正確顯示本卦與之卦。
- 6、9 能被辨識為變爻，7、8 不被誤列為變爻。
- 變爻位置完整列出，且結果頁與逐爻卡片一致。
- 0 個變爻有明確提示；1、2、6 個變爻均能逐一列出。
- 變爻數量為 3～6 個時，顯示之卦卦辭。
- 每個已啟用的結構標籤都有文字說明與規則來源。

### 內容驗收

- 本卦與之卦名稱、卦序、卦象、卦辭彼此不混淆。
- 變爻顯示的是本卦對應爻位的爻辭。
- NotebookLM 匯入的內容保留來源與版本資訊。
- 未完成校訂的內容不標示為已確認結論。

### 品質驗收

- 起卦順序與畫面顯示一致，明確標示初爻至上爻。
- 桌面與手機版均能閱讀六爻圖與變爻卡片。
- 變爻不只用紅色表示，並提供文字或圖示。
- 卦象計算規則有單元測試，結果頁有至少一組人工核對案例。
