## 1. 產品摘要

本產品是一個繁體中文的《周易》研究與閱讀網站。使用者透過逐步互動的揲蓍法模擬取得六爻後，網站計算本卦、變爻與之卦，先提供可追溯的卦象結構資訊，再集中顯示所有變爻的爻辭；當變爻達 3 個以上時，額外顯示之卦卦辭。

產品定位是「卦象研究與經文閱讀工具」，不是自動算命服務，不對使用者產生個人化吉凶或醫療、投資、法律等決策建議。

## 2. 要解決的問題

現有易經卜卦網站通常只呈現本卦、變卦或要求使用者自行查找經文，對初學者有以下困難：

1. 不易辨識哪些爻正在變，以及變前、變後的差異。
2. 不易理解得位、得中、承、乘、應等結構術語。
3. 多個變爻的爻辭分散，閱讀成本高。
4. 經文、注釋、白話與程式判斷容易混在一起，難以追溯來源。
5. 不同流派的規則若未分開，容易產生互相衝突的解讀。

## 3. 產品目標

### 3.1 第一版目標

1. 讓使用者理解揲蓍法「三變成一爻、十八變成一卦」的過程。
2. 正確計算並清楚顯示本卦、變爻與之卦。
3. 以可追溯規則呈現基本卦象結構。
4. 完整提供六十四卦、384 爻及乾坤用九／用六的閱讀資料。
5. 將經文原文、白話、注釋、規則與網站編輯說明分層保存。

### 3.2 第一版不處理

- 帳號、跨裝置同步與永久卜卦紀錄。
- AI 個人化解卦或自動吉凶建議。
- 納甲、五行六親、月建日辰、世應、神煞。
- 沈家銓一卦六伏法、伏卦引擎。
- 高島、朱子、古筮等多套斷卦體例的自動切換。
- 社群留言、公開案例投稿、付款或訂閱。

## 4. 目標使用者

### A. 易經初學者

需要看懂六爻、變爻與基本結構名詞，不希望一開始面對大量未分層古文。

### B. 易經研究者

需要快速查閱六十四卦、384 爻、來源與結構關係，並區分原文、注釋與網站整理。

### C. 想體驗揲蓍法的使用者

希望理解起卦過程，而不是只按一次按鈕得到隨機結果。

## 5. 核心使用情境

1. 使用者輸入一個研究問題，逐步完成揲蓍法，查看本卦與變爻。
2. 使用者查看某個變爻是否得位、得中、與哪個爻相應。
3. 使用者一次閱讀所有變爻爻辭；變爻達 3 個以上時同時閱讀之卦卦辭。
4. 使用者不進行卜卦，直接以卦名、卦序或上下卦查閱六十四卦。
5. 使用者點擊術語，了解「得位」「承」「乘」「應」的定義與規則來源。

## 6. 資訊架構與路由

| 頁面 | 建議路由 | 主要用途 |
|---|---|---|
| 首頁 | `/` | 產品介紹與功能入口 |
| 起卦設定 | `/divination` | 輸入問題、閱讀說明、開始起卦 |
| 揲蓍法互動 | `/divination/cast` | 完成六爻十八變 |
| 卜卦結果 | `/divination/result` | 查看本卦、變爻、之卦與經文 |
| 六十四卦索引 | `/hexagrams` | 8×8 索引、篩選與搜尋 |
| 單一卦頁 | `/hexagrams/:id` | 閱讀單一卦完整資料 |
| 術語索引 | `/glossary` | 瀏覽易經術語 |
| 術語頁 | `/glossary/:slug` | 查看定義、規則與來源 |

## 7. 使用流程

### 7.1 起卦主流程

```text
首頁
→ 起卦設定
→ 逐步揲蓍法（18 變）
→ 六爻確認
→ 卜卦結果
→ 單一卦或術語延伸閱讀
```

### 7.2 中斷與返回

- 未完成的起卦狀態暫存在 `sessionStorage`。
- 同一瀏覽器分頁重新整理後可繼續。
- 返回上一個互動步驟時，還原該步驟以前的狀態。
- 「重新開始」會清除目前起卦資料，執行前必須確認。
- 第一版不永久保存問題或結果。

## 10. 內容來源原則

1. 參考網站只用於頁面與欄位結構，不直接複製全文、圖片或程式碼。
2. 主要內容參考 `參考資料/易經六十四卦_白話 Final_Mike.docx`、PDF 與 NotebookLM「易經經典: Guides to the Zhouyi」。
3. DOCX 與 PDF 均已檢查到 384 筆爻位標題，但仍需處理 OCR、異體字、斷句及亂碼。
4. 不同流派的規則須指定 `ruleProfile`，不可寫入共同欄位後混用。
5. NotebookLM 摘要是研究輸入，不等於已校訂內容。

## 11. 揲蓍法互動規格

### 11.1 操作模式

- **詳細模式**：四營每步按一次，適合學習過程。
- **自動完成本變**：完成目前這一變尚未執行的四營步驟，不跳過整爻。
- 兩種模式使用相同計算結果與歷史紀錄。

### 11.2 狀態機

```text
ready
→ split
→ hang-one
→ count-by-four
→ collect-remainders
→ change-completed
→ 下一變或 line-completed
→ 下一爻或 cast-completed
```

### 11.3 尚待規格化

數位「隨意分握」採用何種隨機策略，須在實作演算法前完成規則規格與統計測試。無論採何種策略，都必須：

- 只產生可完成傳統四營計算的有效狀態。
- 可透過注入固定亂數種子或 mock RNG 測試。
- 不因動畫或點擊速度改變已產生的結果。
- UI 明確標示為數位模擬。

## 12. 視覺與互動原則

- 繁體中文、手機優先。
- 卦象閱讀方向清楚標示「上爻在上、初爻在下」。
- 陰爻、陽爻、變爻同時有圖形與文字。
- 原文採適合長文閱讀的字體與行距；操作介面保持簡潔。
- 主要操作可用鍵盤完成，焦點順序符合畫面順序。
- 支援 `prefers-reduced-motion`。
- 術語解釋使用 popover、drawer 或內嵌展開，不使使用者失去目前閱讀位置。

## 13. 非功能需求

### 正確性

- 領域規則以純函式實作，與 UI 分離。
- 每一條自動結構判斷均有 `ruleVersion` 與來源。
- 64 卦 mapping、384 爻及用九／用六必須通過資料驗證。

### 效能

- 靜態內容頁首次載入應避免一次載入全部長文，可按路由或資料區塊分割。
- 起卦操作不依賴遠端 API；離線載入後仍能完成本次起卦。

### 隱私

- 第一版不要求帳號。
- 問題與卜卦資料預設只存 `sessionStorage`。
- 不把使用者問題傳給 NotebookLM 或其他第三方服務。

### 相容性

- 支援目前主流桌面與手機瀏覽器。
- 以 360px 寬度作為最低主要版面檢查基準。

## 14. 驗收條件

### 起卦

- 能以詳細模式完成 72 個四營步驟，或以「自動完成本變」完成 18 變。
- 每三變只產生一爻；完成順序必為初、二、三、四、五、上。
- 中途重新整理可恢復；重新開始需確認並清除舊狀態。

### 計算

- 6、7、8、9 四種爻值均有單元測試。
- 0～6 個變爻均有測試案例。
- 本卦、之卦與六十四卦對照表測試通過。
- 乾坤用九／用六資料可正確取得。

### 結果

- 所有變爻均顯示本卦對應爻辭。
- 3～6 個變爻顯示之卦卦辭；0～2 個不主動展開。
- 得位、得中、應、承／乘等已啟用規則顯示判定依據。
- 沒有未附來源的個人化吉凶結論。

### 內容

- 六十四卦索引完整且沒有重複或缺號。
- 每卦六爻，合計 384 爻；另有乾用九、坤用六。
- 未校訂內容有清楚狀態，不冒充定稿。

### 易用性

- 360px 手機與桌面寬度皆可完成完整流程。
- 只看灰階仍可辨認變爻。
- 鍵盤可完成主要流程；減少動畫模式可用。

## 15. 發布衡量方式

第一版不設成長或營收 KPI，先看產品是否正確可用：

- 完整起卦流程完成率。
- 起卦過程中放棄最多的步驟。
- 使用者是否能正確指出本卦、變爻與之卦。
- 結構術語說明的開啟率。
- 內容錯誤與校訂回報數。

如加入分析工具，必須匿名化且不得傳送使用者輸入的問題文字。

## 16. 發布前待確認

1. 數位分草的隨機策略及其測試基準。
2. 承／乘與正應／無應規則的最終人工校訂版本。
3. DOCX 或 PDF 何者作為主要內容底稿。
4. 產品正式名稱、視覺風格與部署平台。
